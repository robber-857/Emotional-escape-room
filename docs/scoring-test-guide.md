# 四维计分与手动测试

2026-09-30 修订：取消 A/V/T/F 相加的关卡总分和最终总分。每个维度独立计算，算法版本 `avtf-minmax-v2`。

## 计算口径

每关、每维度分别累计服务器已确认的事件向量。该维度的理论原始范围 [L,U] 来自固定版本的互斥选项，不能把互斥选项累加。可选组包含不触发时的 0。

该关该维度分数 = 100 × (该维原始分 − L) / (U − L)。NA 是未测量，明确的 0 是实际零分；无测量或范围无差异时不伪造分数。

四关完成后，每个维度分别计算：Σ(关卡该维度分 × 关卡权重) / Σ(参与该维度的关卡权重)。原始关卡权重为 L1 20%、L2 30%、L3 30%、L4 20%。NA 关卡排除，缺配置关卡不可跳过。接口返回每维有效权重，便于核对。

最终只有 A、V、T、F 四个 0–100 分。真我值读取 T，恋爱脑指数读取 F。沿用已确认五星区间：[0,20)、[20,40)、[40,60)、[60,80)、[80,100] 分别为 1–5 星。16 类画像映射仍使用独立策略入口；本轮不猜测其高低阈值或类型映射。

## L2 整理房间：已启用

用户确认固定四档边界，版本 `l2-fixed-quarters-v1`，不是等待采集样本池。

| 指标 | 边界 | 从低值档到高值档的得分 |
| --- | --- | --- |
| 靠墙／窗程度 | 0.25 / 0.5 / 0.75 | A：−2 / −1 / +1 / +2 |
| 整齐度（1 − 重合程度） | 0.25 / 0.5 / 0.75 | F：−2 / −1 / +1 / +2 |
| 调整次数 | 暂定上限 20，等价原始次数边界 5 / 10 / 15 | T：+2 / +1 / −1 / −2 |

次数归一比例为 min(次数 / 20, 1)，原始次数仍完整保存。边界相等落入较低原始值档：5 次 +2、10 次 +1、15 次 −1、16 次及以上 −2。上限和边界在版本配置中可修改，只影响新旅程。

桌前椅继续使用较窄重叠核心，没有朝向、旋转评分。每次确认更新候选结果，第一次正式进入第三幕时按最后确认的布局和当时累计调整次数结算；确认本身不计分。进入第三幕后第二幕不可修改，重复进入不重复结算。拖动时即限制在允许的地面接触范围，可沿墙滑动，确认时不再以越界拒绝评分。前后端使用同一边界函数；旧未确认布局在重新整理时收回范围内，历史已确认回执不变。

## 当前其他空缺

L2：失败后放弃重试；探索；不找耳环、短搜后放弃、短时间找到耳环的分值未配置。重试放弃、探索、搜索的部分触发条件／截止点仍未定义。座位、第一次试门、第二次重试、整理房间已接计分。桌前椅等同文档中心椅 A−1，窗边椅 A+1，未坐直接到桌边 A0，其余维度 NA。截止点暂按推荐方案：首次成功坐下或首次到桌边；后续换座不重算。

L3：仅“未开但选择关门”和“带走背包”缺结果分值，其余已配置。缺失向量尚不能确定影响哪些维度，因此不能擅自认定它对某维无影响。已知仅涉及某维的配置空缺则只阻塞相应维度。

## 测试入口

打开 http://localhost:3000，从第一幕开始新旅程，展开右下角“服务端计分”。后端 http://localhost:8000。旧合计算法旅程提示重新开局，不改写历史回执。

面板显示每关四维原始分、归一化分、逐事件四维增减、事件 ID、结算证据，以及分值／条件／边界的具体待配置原因。每秒读取服务器账本，纯前端点击不产生计分。星号是暂算值。灯在 L1 结束结算；窗／电视在六项回答完成时结算；家具进入第三幕时结算最后确认结果。L3 开门、关门均为是时，组合已不可变，立即结算；其他门结果仍可从否改是，等六项回答完成结算。历史回执记录的是当时状态，不会被后来的结算回填；新版提示列出当时尚未回答项。

同 ID 重试返回原回执，新 ID 重复结算不重复加分；断网显示错误，恢复和刷新重新读取账本。第四关弹窗点“稍后再看”后可展开面板。

接口：动作 `score_effect` 与鉴权 `GET /api/v1/sessions/{id}/scoring`。状态、账本、回执同事务提交。配置完整快照随旅程绑定，后续配置不改写旧回执。

验证：PostgreSQL 229 项、前端 68 项及类型检查通过。浏览器桌面／触屏联测包含真实 UI 展示、刷新与断网恢复；L2/L3 的部分前置过程由鉴权 API 完成，不等同所有事件人工 UAT。

本轮修复版本：`server-composite-v3` / `event-scores-v2` / `l2-validation-v9`。旧评分版本需要新旅程测试，不回写用户原有事件。新增桌面／触屏联测脚本 `apps/api/tests/uat/l2-l3-scoring-regression.js` 复现桌前椅、边界摆放及开关门立即结算。

家具拖动边界 `l2-placement-v6`：依据占地区域而非完整图片。左右放宽地面坐标 0.02，前沿放宽 0.04（设计稿约 11 像素）；后墙接触边为 v=0.12，结合家具半深度计算中心限位。鼠标、触摸、键盘及服务器提交一致限位，撞墙不产生额外调整次数。F 仍只依据重叠，不增加越界扣分。桌面／触屏真实拖动及确认计分通过，脚本为 `apps/api/tests/uat/l2-wall-drag.js`。

结算补充：确认之后继续移动但未再次确认时，使用上一次确认的布局与次数，不把草稿混入评分。入口已提示重新确认。每次确认的历史回执不可变；第三幕创建与家具评分使用同一事务、同一旅程锁。测试台会显示“已保存最新确认，进入第三幕时结算”，并在进入后新增“结算最后确认的摆放”事件。算法定义版本已升级，旧已计分旅程不回写，需新旅程测试。

## 靠墙程度 v2 与四档显示

界面统一显示“第 N/4 档”，固定阈值 0.25/0.5/0.75 称为四档，不再显示内部选项编号拼成的“2 / 2”。等于边界仍归较低原始值档。T 的低次数档仍是正分。

单件靠墙程度 = 1 − clamp((d − P) / (Dmax − P), 0, 1)。d 是占地区域到后／左／右最近墙面的间距，后墙与拖动边界统一取 v=0.12；前沿不是墙，窗户不额外加分。距离为统一地面坐标单位，不是屏幕像素或真实米数。P 暂取 0.02，贴墙容差内均为 1。

Dmax 根据固定房间与家具占地尺寸计算：给定深度时取左右间距中点，再对允许深度范围做 80 次三分搜索，结果按家具缓存。它不依赖玩家本次走过哪些位置。数值解精度由独立二维网格校验；最终使用四件家具靠墙程度的平均值。

| 家具 | Dmax 约值 |
| --- | ---: |
| 单人沙发 | 0.425288 |
| 窗边椅 | 0.479808 |
| 双人沙发 | 0.368768 |
| 桌椅组合 | 0.341407 |

服务端确认记录及最终结算事件提供每件家具的 d、Dmax、P、靠墙程度，界面“靠墙程度计算明细”可展开查看，最后一行显示平均值。F 重叠、T 次数和进入第三幕取最后确认的规则不变。

可达性：四档均已覆盖；固定回归布局达到靠墙程度 0.236525、整齐度 1.0，即 A−2、F+2 可以同时出现，不要求严重重叠。该证据证明档位可达，不等同真实用户分布已均衡。

版本：指标 l2-metrics-proximity-v2、固定边界 l2-fixed-quarters-v2、事件定义 server-composite-v4。旧已确认旅程不重算，需新旅程测试。验证：PostgreSQL 233 项、前端 69 项及类型检查通过。
