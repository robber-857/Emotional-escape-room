## 发现与处理

| 问题 | 影响与处理 |
| --- | --- |
| P2：更换物品可耗尽最后事件额度 | 第 400 次若是 draft，confirm 也会被事件上限拒绝。现在第 399 版不再接受更换，返回 `CONFIRM_SLOT_RESERVED` 并保留预选，最后一次用于确认；已补边界测试。 |
| P2：逐事件校验依据未单独留存 | 旧回执只有版本、来源和结果。新 `l3-validation-v2` 在同一事务保存鉴权/前置、版本匹配、流程是否执行/通过及额度检查；跳过的检查不标为通过。旧回执与同 ID 重试保持原样，不补造历史。 |
| 前端来源说明集中在列表顶部 | 现在每条回执分别展示服务器记录/判定来源、客户端输入、状态是否推进和服务器保存的校验依据。缺少来源或旧校验数据时明确标注，不由当前状态反推。 |

## 复查结论

未发现本次已覆盖路径中可绕过 L2 通关、伪造 state/score、重复确认物品或同 ID 重复推进的问题。L1 原会话行锁串行化 L2/L3 写入，回执与状态同事务；失败回滚、同 ID 不同 payload 拒绝、并发版本冲突都有 PostgreSQL 测试。GET 历史直接读取回执表，评分维持待配置/null。

保留边界：400 是状态变化额度，不是审计回执数；拒绝/重复确认回执仍可增长，公开部署前的限流和历史分页尚未实现。SQLite 不提供 PostgreSQL 行锁证据。终态不解锁 L4，不生成正式评分/报告，也不提供清除服务器历史的接口。
