## 3. 图层与交互架构

全视口外壳使用 Grid 居中等比舞台，无底部控制面板。提示为舞台内 HTML 定位层（随物件归一化位置移动，边缘限位）；菜单为视口覆盖层。
舞台使用 SVG viewBox 0 0 2944 1568 等比缩放；场景逻辑坐标不随屏幕改变。
Scene.tsx 按顺序组合 background → water-effects → scenery → hit-regions → props；对岸使用 background → characters → props → hit-regions。
Sprite.tsx 与 fills.json 管理图像裁切/变换；命中区域独立于图片，静态装饰不拦截 pointer。
河面 10 秒 / 6 秒光点交替明暗。prefers-reduced-motion 或菜单开关可关闭动效。
图层内部坐标和提示分离，提示不缩到不可阅读；一次只显示当前物件的有效提示，完整尺寸 HTML 按钮提供触屏/键盘替代入口。

木板、绳子、救生圈：
- Pointer Events + pointer capture，使用 SVG screen CTM 逆矩阵转换触点。
- 超过 16 个场景单位判定拖动，拖动结束抑制随后 click，不误触发选择。
- 保存归一化位移 x/y；边界约束在舞台内。
- 取消手势回滚，键盘方向键可微调，菜单可恢复摆放。
- 普通位移只保存位置；木板和绳子中心都进入 geometry.ts 定义的缺口区域后，提交拾取（如果尚未拾取）及修桥事件。取消手势不提交；修桥不自动过河。
- 道具点击轻微抖动；划船每个动作有短暂输入锁，避免一次双击被当成多次划桨。

## 4. 状态与有效提示

| 阶段 | 前置条件 / 操作 | 状态变化 |
| --- | --- | --- |
| 看断桥 | 尚无木板 | 提示去查看木板，不提供“立即过桥” |
| 拾取木板 | 还未拾取且未修好 | 进入搬动提示，木板仍留在场景可拖动 |
| 修桥 | 木板和绳子中心都落入缺口 | 消耗木板、1.2 秒显现完整桥背景；不自动过河 |
| 走桥 | 桥已修好，明确选择是 | 到达对岸，route=bridge |
| 游泳 | 河岸、未开始划船 | 明确选择是后到对岸，route=swim |
| 救生圈 | 河岸、未开始划船 | 明确选择是后到对岸，route=ring |
| 搜草丛 | 未找到船桨、未上船 | 每次点击 +1；第五次船桨跳出并安装在船边 |
| 上船 | 已有桨 | 进入划船阶段，其他路线不可提交 |
| 划桨 | 正在船上 | 1–4 次留在河上；第 5 次到对岸；重复事件 ID 不再推进 |
| 打招呼 | 对岸、未打过 | 记录 greeting；不自动拿灯或进门 |
| 拿灯 | 对岸、灯未拿起 | 可带走未点亮的灯 |
| 点灯 | 对岸、灯未点亮 | 可原地点亮或拿起后点亮 |
| 进门 | 对岸 | 结束 L1 前端预览；不跳到未实现的 L2 |

所有明确“否”保存独立事件、保持场景且允许重新选择；关闭提示只关闭 UI。
人物、灯和进门的操作顺序完整保留；没有操作不记录为显式拒绝。
结束后阻止新的剧情动作。客户端按唯一 event.id 去重。
这些是前端交互规则；服务端接入后必须重新验证所有动作，不能信任本机日志。

## 5. 本轮工程默认值（待产品/设计 review）

设计提供物件和提示，但未完整定义所有操作文案与动画。本轮采用：

- 水面与道具动画为可关闭的表现层，不决定正式行为分数。

上述文案与操作语义应在正式评分映射时逐项确认。不要直接将这些预览事件映射为未经核对的 19 条 L1 评分规则。

## 6. 本机保存与恢复

localStorage key：emotional:l1:preview:v2，结构包含 version、events、positions、savedAt。
每次有效选择和拖动结束同步写入；刷新、保存返回后可继续。
restore 逐个验证并重放动作，拒绝非法顺序、重复 ID、未知动作、损坏 JSON 与不兼容版本。
写入失败显示明确状态；不显示“已同步云端”。多标签页变化冻结交互并提示重载。
保存的是已执行动作和物件位置，未确认的当前提示不保证恢复。
本机数据可被用户修改，不承担安全边界。不保证浏览器清理数据后的恢复，不保证未缓存页面的离线加载。
完整服务端检查点 / IndexedDB outbox / 版本冲突 / 授权访问仍按 save-and-resume.md 后续实现。
