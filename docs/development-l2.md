## 1. 已确认与建议分界

已确认：每局提供 L2-01 座位/钥匙、L2-02 半开门、L2-03 耳环、L2-04 家具四组，不随机抽取。家具“整齐”只需看似合理，不要求复原某个标准答案；凳子不能放在沙发上，沙发不能明显悬空，贴近地面的小误差允许。

2026-09-28 用户确认：到达桌边，或者在座位提示中选择“是，坐下”，任一条件满足后即出现选择钥匙的提示。两者为 OR 关系，不要求先到桌边再坐下，也不要求触发后再点击钥匙才显示选择提示。显示提示不等于已选定、拿取或尝试钥匙。

用户已确认空旷指一件家具放在空旷位置；具体空间阈值为可调工程初值。它们不改变 A/V/T/F 分值，不把摆放解释为心理诊断。

最新规则优先于此前“不自拟空间判断”的限制：可以设计家具合理性校验；未确认的空旷算法只可作为可调原型建议，不能作为正式计分依据。

## 3. 玩家流程与四组交互

进入 L2 → 大厅探索 → 点击物件显示当前气泡 → 执行动作/返回探索 → 保留四组各自状态。
不同时铺满四组问题，不增加页面下方控制面板。移动草稿和剧情选择分别记录。

| 组 | 场景与操作 | 提示建议 | 行为与反馈 |
| --- | --- | --- | --- |
| L2-01 座位 | 点击可坐的椅子或沙发 | “要在这里坐一会儿吗？” 是 / 否 | 记录实际座位 ID；选择坐下后出现钥匙选择提示；否后仍可探索，不擅自给钥匙 |
| L2-01 钥匙 | 到达桌边，或确认坐下后显示选择提示 | 建议文案：“桌上有两把钥匙，你想先选哪一把？” | 玩家明确选择具体钥匙后才更新物品状态；提示出现本身不算拿钥匙，也不把 hover 当比较 |
| L2-01 试钥匙 | 选定钥匙后点击对应门锁 | “用这把钥匙试试？” 是 / 否 | 已确认第一次实际尝试必失败；同一把标记为无法打开；必须换另一把进行第二次尝试，第二次成功 |
| L2-02 半开门 | 点击半开门 | “门留着一道缝，要推开看看吗？” 是 / 否 | 是后进入设计对应视图；否保留现场，后续通行不擅自认定为完成 |
| L2-03 耳环 | 点击卧室搜寻点 | “这里好像少了一只耳环，要找找吗？” 是 / 否 | 同意后才开始有效搜寻计时；耳环点击后显示独立反馈，返回主厅按钮始终清楚可见 |
| L2-03 返回 | 未找到时点击返回 | “先回大厅吗？” 是 / 否 | 明确返回才结束本段寻找；关闭气泡不算放弃，不显示计分倒计时诱导玩家 |

| L2-04 确认 | 玩家主动结束摆放 | “就这样摆放吗？” 是 / 否 | 是验证并保存一次布局快照；否继续移动，不清空草稿 |

钥匙规则已确认：不设“反复比较”独立事件，仅记录实际第一次/第二次开门；第二次必须换另一把钥匙。拒绝钥匙/半开门后的整体通行仍需补齐。以上提示是可审阅的补充文案，不宣称来自 Figma 原文。耳环有效寻找严格 >15000ms 为长寻找，返回时 <=15000ms 为短寻找；暂停、后台、加载与竖屏提示期间不累计。

## 4. 整齐与空旷事件（2026-09-28 最新规则）

用户确认：整齐只要求看起来合理，不要求朝向一致、对称或对齐；允许轻微重叠，拒绝高度重叠。空旷表示**一件移动过的家具放在空旷处**，一件即可触发，不判断摆完后房间剩余空地面积。

采用脚底在逻辑地面的占地矩形判断，不使用整张图片的包围框。透视造成的图片遮挡不直接判为堆叠。桌椅组合为一个占地，两个沙发、窗边椅、桌椅组合共四件；电视柜仅在整理模式隐藏。

| 判断 | 当前实现 |
| --- | --- |
| 合理摆放 | 所有占地在可放地面内；任意两件占地交叠面积不超过较小占地的 20% |
| 有效移动 | 相比上次确认布局（首次为初始布局），中心移动距离至少 0.02 归一化地面单位 |
| 整齐事件 `tidy` | 确认布局合理且至少一件有有效移动；不要求移动全部家具 |
| 空旷事件 `open-placement` | 至少一件有效移动家具满足下述目的地净空条件 |
| 目的地净空 | 与其他家具占地距离至少 g；四边至少三边净空带无家具且在地面内，其中 g=max(0.025, 家具较短边×0.30)，净空带宽为 2g |

20%、0.02、g 与三边净空是本轮工程初值，可根据试玩调整，并非用户指定的数值标准。允许一边靠墙；落点可以合理但不满足空旷。地面仍为手工标定梯形，边界容差为 0.015；它不是图像识别，素材脚底和地面边界仍可能需要校准。

## 5. 触发时机与验证证据

有效松手保存草稿，**点击确认摆放后**统一计算事件。撤销后回到基准位置不触发；仅打开整理、无移动确认、无效拖动均不触发。退出整理保留草稿，但不提前触发。每次确认更新基准；两个事件各在本机进度中累计触发一次，可以同次触发，也可以后续补触发。后来移走家具不会抹除已发生事件。

规则版本为 `l2-placement-v2`。确认结果包含 `reasonable`、`tidy`、`openPlacement`、`movedIds`、逐件起止位置及净空证据 `placements`、本次新事件 `events`。本机保存仍为动作序列；刷新重放不追加事件，旧预览动作会按当前规则重新分类，不属于不可变服务端审计记录。

菜单“查看本机选择”可查看累计事件、最近确认规则和本次新触发。玩家正常场景只提示保存，不展示空间数值或分数；不空旷也允许保存。旧的中央空地、25%面积、通路连通分类已移除。L2 仍未接入服务器校验及正式 A/V/T/F 评分。

## 8. 验收案例

- 到达桌边但未坐下：出现钥匙选择提示。
- 在座位提示中确认坐下：出现钥匙选择提示，无需额外点击桌上钥匙。
- 仅打开座位提示或选择不坐，且尚未到达桌边：不以“已坐下”条件触发钥匙提示。
- 提示刚出现时不自动选择或拿取钥匙；只有玩家明确选择才记录相应行为。

- 凳子放沙发坐垫：无效；沙发放墙面高处：无效；脚底仅差容差范围：吸附后有效。
- 椅子在沙发前正常遮挡：有效；落地但实体穿插：无效；不对称但合理：可确认。
- 只移动一件到空旷目的地并确认：触发空旷；移动到轻微重叠处：可整齐但不空旷；未移动或撤销回原位：不触发。
- 将家具拖出画面、藏在另一家具里不能制造空旷；撤销/恢复/刷新保持正确位置。
- 四组均可提供；拒绝和未操作不混同；15 秒边界、后台暂停、重复确认均有测试。
- 桌面/手机横屏在同一逻辑地面位置得到同样判断；气泡不截断、不遮住当前拖动目标。

L2-01 的当前实现范围见第 6 节；其他三组、空间算法和正式评分未实现。验证证据见 progress.md。

## L2-03 耳环搜寻（2026-09-28）

进入卧室后点击梳妆台（场景命中区或导航入口），出现“这里好像少了一只耳环，要找找吗？”；否保留卧室并可重选，关闭不记拒绝。是才开始本段寻找。耳环使用 Figma 119:67 原始独立素材及裁切，位于床头柜附近；开始前不能拾取，开始后点击耳环显示“找到那只耳环了。”，原位置移除，不重复拾取。

未找到时返回大厅先询问“先回大厅吗？”，取消/关闭继续探索；确认返回结束当前段。再次进入并同意寻找开启新段，原事件保留；已找到时返回或再进入都保留找到状态。

本机 `search-choice`、`search-time {activeMs}`、`find-earring` 与现有 `return-hall` 记录事实。activeMs 使用 performance.now 的活动区间累计，严格 >15000ms 标记长寻找；<=15000ms 返回属于短寻找，等值仍在找不记长寻找。菜单、提示、加载、竖屏、document hidden、离线期间暂停，无倒计时或分数提示。计时不自动找到耳环。

每约5秒、跨过长寻找阈值、暂停和 pagehide 保存活动时长，拾取前也结算；刷新不累计关闭/加载间隙，恢复本段。异常杀进程可能丢失最近不足5秒的未写入时长；这仍是可被本机修改的前端记录，不冒充正式后端有效时长或评分。沿用 v2 存档，旧事件可恢复。

耳环的拾取区域独立于图片，适当放大以便触屏操作，不在界面提前标示位置。键盘也可聚焦拾取。家具摆放 L2-04 尚未实现。

### L2-03 两只耳环修订（2026-09-28，覆盖之前直接拾取规则）
