# L1-02 人物打招呼：进入第二幕结算

2026-10-06 用户确认：男女两个事件分别结算，选“是”、选“否”和未作答直接进入第二幕三选一。新旅程使用 `event-scores-v8-l1-greetings`，结算策略为 `greeting_settlement_version=l2-entry-v1`。

| 结果 | 服务端判定 | V | A / T / F |
| --- | --- | ---: | --- |
| `yes` | 男生 `greeted=true`；女生 `greetedWoman=true` | −2 | NULL |
| `no` | 该人物有已接受的“否”回执，且最终未选“是” | +2 | NULL |
| `skipped` | 该人物没有已接受的打招呼回答 | 0 | NULL |

男生使用 `l1.talk.man` / `greet`，女生使用 `l1.talk.woman` / `greet-woman`。此前选“否”后改“是”，最终只结算 `yes`。被服务器拒绝的回答不参与判定。两个评分组各生成一条账本，V 理论原始范围为 [−4,+4]；两人均未作答时，V 原始分为明确的 0，归一化为 50，并非未测量。

L1 内回答先保存原始回执，计分原因显示 `AWAITING_L2_ENTRY`；点击人物打开提示不计分。关闭提示不会提交“否”，因此只打开后关闭提示仍按 `skipped` 处理。当前服务端不记录提示点击，`skipped` 只证明没有已接受的回答，不证明从未点击人物。

第一次鉴权 `POST /api/v1/sessions/{id}/levels/l2` 创建正式第二幕时，读取 L1 的最终状态与已接受事件并统一结算；L1 的 `enter` 动作、仅打开 L2 页面但未成功创建，以及预览都不触发人物评分。过河和灯保持原来的截止点。新版 L1 的评分完成状态等待成功进入 L2，之前显示暂算分。

L2 创建与人物结算共用旅程锁和数据库事务。结算生成独立的 L1 `greeting-finalize` 评分回执，保留原始 L1 回执。每条账本保存 `evidence.settlement=l2-entry`、`rule_version`、`greeting_action_ids`、`cutoff_state`、`source_action_ids`、L1 截止版本及绑定策略 hash；刷新、重试、并发进入不会重复结算，失败时一起回滚。

旧旅程继续使用创建时冻结的评分策略。V7 的“是”仍在当时动作评分，“否”及未作答不自动补分；未绑定评分的旧旅程也不补造评分。此改动只作用于新绑定 V8 的旅程，不回写旧回执或已结算账本。
