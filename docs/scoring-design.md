# 当前评分规则与配置边界

> 2026-10-02 最新：新旅程使用 `event-scores-v6-search-exit` / `found-or-l2-exit-v2`。第三次点击窗帘找到时，≤15秒 A=0、>15秒 A=+2；选择不寻找或短搜后放弃（≤15秒）先保存状态，首次进入 L3 时按最终状态结算 A=-2，长搜后放弃仍为 A=+2。中途重返并找到只记找到结果，不叠加放弃扣分；从未作出搜索选择不补造放弃事件。V/T/F 为 NULL。离场结算与 L3 创建同事务，独立于家具确认截止点，重复进入不重算。旧旅程保持原策略。

更新：2026-09-30。优先级：用户确认 > 当前本地事件/触发条件 > V6.2向量来源。旧草案移至[历史设计](history/scoring-design.md)，不得以旧的逐操作累加方式实现。

原始操作留回执；多个操作满足完整条件后，命中一个评分组的一个结果，只计一次。同ID重试和新ID重复操作都不能重复加分。组内互斥结果不叠加；仅no_effect的否不影响分数，原表有明确否结果的按组处理。

| 评分组合 | 最终条件 | 一次向量 |
| --- | --- | --- |
| 修桥后过河 | 修桥成功且route=bridge | A+1、F+1 |
| 修船后过河 | oar=true且第五桨route=boat | A+1、F=0 |
| 灯 | 点亮且带走 / 点亮未带走 / 未点亮带走 / 均未做 | F+2 / 0 / 0 / −2 |
| 关窗与关电视 | 关窗关电视 / 关窗开电视 / 开窗关电视 / 开窗开电视 | F+2 / 0 / 0 / −2 |

灯在L1结束时取lampLit/lampTaken；窗/电视在六项回答完成、storm转carry时取choices.window/television。未答null不是false；否后是以截止时最终状态为准。上述四维未列出的轴为NA，F=0必须保留为明确零值。电视替代原表电扇已获用户确认，数值不变，无需新增风扇事件。

配置实现：固定评分 group_id/option_id 及组合条件由规则层维护；数值位于 apps/api/app/config/event-scores.json。加载器、版本快照、事务账本及服务端计分面板已实现；当前 event-scores-v4-temporary-null 按用户确认将未配置选项临时设为 NULL，不补零；未来补分发布新版本。每关 A/V/T/F 分别按该维理论范围归一化至 0–100，四关齐全后同维度按 20/30/30/20 的相对权重汇总；NA 排除，缺配置不能跳过。不存在跨维度总分。公式、测试入口和限制见 [计分测试指南](scoring-test-guide.md)。

完整规则与测试要求见 [开发任务](scoring-receipts-development.md)。[用户确认的最终对照表](../outputs/01a0ed34-event-audit/本地事件与V6.2评分组合比对表_电视确认版.xlsx)保留48个评分结果候选、44条操作归属和64条原表来源；这不是48份累计加分。背包、探索节点和部分截止点仍需确认。家具固定边界已启用，详见测试指南。
