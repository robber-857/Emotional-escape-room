# 可调整评分、关卡权重与结果版本

日期：2026-09-25。本文为实现设计，未校准参数不代表已确认的心理测量标准。

## 1. 四个维度，不是一个“好坏总分”

PDF 定义 A=依恋焦虑、V=依恋回避；A/V 决定依恋区域。T/IFS、F/Gestalt 只是游戏化行为修饰轴，细分为 16 型，不能变成额外临床心理指标。

因此“结果分数比例 2:3:3:2”建议解释为对 A/V/T/F 每一轴分别应用 20%/30%/30%/20%。不把四轴相加成一个排行榜总分。结果页文案强调游戏中的倾向，不制造“越高越优秀”的含义。

## 2. 评分数据链路

原始动作 → 校验状态与证据 → 有限次行为归类 → 关内计分单元 → 关卡归一化 → 四关加权 → 边界判断 → 16 型与文案快照。

UI 只提交动作，例如选择门或确认家具位置，不能提交 +2、依恋类型或可任意修改的 score。所有增量来自服务端发布版本。

保留三个不同层次：
- action：原始动作，如看灯、选择不点亮、拿走灯、进入门。
- outcome：可计分的行为结果，如“拿走未点亮的灯后再与人交谈”。
- contribution：某个规则给 A/V/T/F 的实际增量及来源。

不是每次点击都产生评分。拖动、hover、查看说明、网络重试、同一物件反复操作不能刷分。

## 2.1 用户确认的三层计分与 UAT 展示

必须逐层展示：每个 action 的实际计分处理 → 每关的独立总分 → 四关加权后的最终结果。不能只在 L4 结束后返回一个汇总类型，也不能要求先玩完四关才能查看 L1 的得分。

这里“关卡总分”保留 A/V/T/F 四个分量：raw_total（有效行为原始累计）和 normalized_total（参与跨关加权的统一量纲得分）。不擅自把四轴相加成一个失去性格含义的单数值。权重 2:3:3:2 已确定；关内归一方法与阈值仍按本文草案冻结流程确认。

**Action 层：**
- 对每个离散游戏 action 记录 action_id、level_id、scene_id、服务端顺序、前后状态/评分 revision、命中 rule_id、规则版本和来源。
- 展示该 action 是否触发加分/减分/零分、四轴实际净变化、触发前后本关 raw_total；无计分也必须解释原因。
- 区分 scored、no_score、pending_sequence、rejected、duplicate。尚未完成的序列显示“待判定”，不能为展示即时加分而改变规则的结算时机。
- 复合行为结算记录 trigger_action_id 与 contributing_action_ids，可以从最终贡献反查全部相关动作。早先动作保留原记录，并链接后续结算。
- 替代先前贡献时显示撤销旧贡献、新贡献和本次净变化，不能在总分中保留被替代项；重复请求本次新增贡献为 0，并关联原成功动作。
- 本地待同步动作标为“未到达后端”，不能显示为已计分。连续 pointermove 不逐帧上传计分，按草稿采样与离散确认记录。

**关卡层：**
- L1/L2/L3/L4 各自有独立动作明细、当前累计与结算摘要，可以按关卡查看或导出。
- 每个有效 action 处理后即可查询当前累计，标记 provisional；合法完成本关后形成 finalized 关卡快照，不等待其他关卡。
- 快照包含有效贡献 ID、截至事件序号、raw_total、各槽的 r/B/alpha、normalized_total、coverage、权重、weighted_contribution、规则版本和结算时间。
- 未开始、进行中、已完成分别展示；进行中不得冒充已结算，未完成关卡不得按 0 结算成正式最终结果。
- 已完成关卡快照不可被后续关卡动作修改；重复恢复或结算返回同一快照。规则变更下的分析重算另存新记录。

**最终层：**
- 引用本会话四份 finalized 关卡快照，而不是跳过关卡汇总直接打包全部事件。
- 对每个维度 d：raw_total[l,d] = 本关当前有效 contribution 的增量之和；normalized_total[l,d] = 100 × L[l,d]。
- weighted_contribution[l,d] = normalized_total[l,d] × weight[l]。
- final[d] = L1.normalized_total[d] × 20% + L2.normalized_total[d] × 30% + L3.normalized_total[d] × 30% + L4.normalized_total[d] × 20%。
- 最终页面按四关列出归一分、权重和加权贡献，再展示四轴合计与人格判定；内部判定不使用显示四舍五入值。

对账必须同时成立：
1. 每个 action 后的累计 = 前累计 + 本次净变化（含合法替代的撤销量）。
2. 关卡 raw_total = 该关最终有效贡献之和 = 从零累加本关全部已提交净变化。
3. 关卡 normalized_total 能按快照中的槽分母和权重复算。
4. final = 四份关卡 weighted_contribution 之和。

## 3. 去重、顺序与互斥

每条规则至少包含 rule_id、source_page、source_row、level_id、group_id、decision_slot、前置条件、结果条件、触发时机、向量、最大触发次数、互斥/覆盖关系。

- 互斥选项：如 L4 四扇门，同一槽只记录一个最终确认结果。
- 用户已确认 L1 重叠行为全部累加：“直接进门”“不选人直接进密室”“拿未亮灯直接进门”等只要各自完整条件满足，就分别产生贡献。不采用最具体优先、命中首条即停或排斥较宽泛规则。相关终态规则在场景离开时统一判定，并逐条展示命中的 rule_id、向量与累计结果；“不选人”等终态条件不能在尚可继续操作时提前判定。
- L2 先否后是：先完整保存原动作序列；具体通行与序列结算细节随设计师讨论冻结，不把之前“仅最终序列计分”的建议当已确认规则。L1 则已明确所有匹配规则全部累加。
- 用户已确认 L3 携带累加：选择“是”和最终确认具体物品分别计一次，再累加。例如按 PDF 基线，“是”=(+2,+2,+2,+2)，围巾=(-2,-1,-1,-1)，两项合计=(0,+1,+1,+1)，维度顺序为 A/V/T/F。物品确认前切换仅为草稿，不增加贡献；选择“否”只产生“不带”的贡献。
- 用户已确认船桨必须完成 5 次有效操作才计分：计数从 4 变为 5 时触发一次 PDF 对应向量 (-1,-1,-1,+2)。前 1–4 次显示进度与计分 0；完成后重复点击或补发不再次计分。计数和触发标记随场景存档，重试同 action_id 不增加次数。
- 一个 action/计分槽可命中多条不同规则，不得以 action_id 或 decision_slot 单独唯一约束丢掉合法累加项。逻辑贡献唯一键使用 session + rule_id + scoring_scope + occurrence_index；scope/occurrence 由后端状态机分配，单次规则固定 occurrence=1。action_id 独立用于请求幂等；合法更正保留贡献修订链，不能生成新 occurrence 规避去重。
- 重新开始是新会话；旧结果只读。

## 4. 为什么先归一化

L4 只有一次出口选择，L3 有多项行为。如果直接将原始分乘以关卡权重，事件多的关卡仍然会占更大影响，与 2:3:3:2 的设计意图不一致。

推荐首版数学方案（待通过路径模拟与产品评审）：

对关卡 l 的计分单元 g、维度 d：

~~~
r[l,g,d] = 本单元最终有效贡献之和
B[l,g,d] = 此版本所有合法终态中，abs(r[l,g,d]) 的最大值
n[l,g,d] = r[l,g,d] / B[l,g,d]                  # [-1, 1]
L[l,d] = sum(alpha[l,g] * n[l,g,d]) / sum(alpha[l,g])
S[d] = 100 * (0.2*L[1,d] + 0.3*L[2,d] + 0.3*L[3,d] + 0.2*L[4,d])
~~~

这里计分单元是版本化的 decision slot，可以覆盖一个选择阶段或一段复合顺序，不机械按 PDF 标题数量分组；group_id 用于组织内容组，slot 用于计分机会。同一 slot 内允许多条符合条件的 L1 规则累加；r 为全部有效贡献之和，B 必须按允许累加后的合法路径总和重算，不能仍按单条最大分数设上界。归一化不能用来抹掉用户确认的有效累加。

B 由规则、互斥条件、触发上限和合法路径确定，不使用“当前玩家点击数”作分母，也不使用运营样本的最大值动态改变老会话。若 B=0，此槽该维度不提供信号，按 0 处理并标记，不做除零；发布检查必须识别该关卡是否因此完全缺失某维度。alpha 初始建议相等，可配置，尚未冻结。

合法完整关卡的 L ∈ [-1,1]，故四关对每轴理论最大绝对贡献分别为 20/30/30/20。实际玩家结果不要求每关恰好占其数值的对应比例，也不保证各关真实人群方差一致；后者需试玩校准。

示例：某一轴四关归一分为 0.50、-0.20、0.80、-0.50：
S = 100 × (0.2×0.50 + 0.3×(-0.20) + 0.3×0.80 + 0.2×(-0.50)) = 18。
这只是公式示例，不是从 PDF 推得的真实玩家结果。

避免直接使用 min-max 映射默认把不对称范围中点当中性。上述最大绝对值缩放保留原始 0 的中性含义。

## 5. 固定四组与缺失数据

用户最新确认：L2 四组全部制作、每局四组全部提供，不随机抽取。因此本版本 L2 的计分槽集合固定，不存在不同抽取组合的分母差异。

- 四组都必须到达完成或显式允许的拒绝/跳过终态。正常跳过也保留该组计分槽，不通过删除分母放大其他行为。
- 因合法路线未抵达的槽标记 not_reached；未交互标记 not_observed；真正选择“不”记录 explicit_decline。这三者不能混用。
- 对合法完成但未抵达的预定槽，建议保留槽权重、贡献为 0，并降低 coverage；零贡献不是“已观测到中性”。
- 未完成关卡不能通过移除其权重，把剩余三关重新归一到 100%；未到终态时只保存进度，不发正式结果。
- 每关/每轴返回 observed_slots、eligible_slots、coverage。低覆盖的处理策略需冻结；建议结果加证据不足说明，确实无证据时不强制生成一个看似精确的类型。
- 通过路线设计保证正常完整体验有足够信号，而不是事后凭空补分。
- L2 拒绝钥匙/半开门后的其他组访问与过关由设计师讨论后决定。当前不定义独立出口、重新进入或跳过动作；依赖此路径的完整验收标记 Blocked，不伪造缺失分支得分。

对固定四组的所有合法路径进行枚举或有界采样，检查各轴范围、0 分比例、覆盖率与类型可达性。数学归一不等同于心理等价，仍需试玩校准。未来若重启抽题，必须发布新的内容与评分版本，不在本局中途换题。

## 6. 时间和空间行为

耳环：
- PDF 的原始时间描述已由用户补全：长寻找严格大于 15 秒；返回时小于或等于 15 秒按短寻找。
- 用户已确认长寻找严格使用 elapsed_active_ms > 15000；15000ms 不触发长寻找，15001ms 在持续寻找条件满足时可触发。返回主厅时 elapsed_active_ms <= 15000 按短寻找，等值继续寻找则保持待定。按后端有效活动时长比较，不先四舍五入成整秒。
- 只统计物件可交互且页面处于前台的有效活动时间；旋转提示、后台、加载、断线不计入。
- 服务端以活动租约与心跳确认区间，最后确认活动后的无心跳时间不追加；客户端立即暂停。恢复携带序号并核对检查点，不能只相信前端上报任意毫秒数。
- 心跳间隔、丢失宽限和阈值附近误差需在原型实测后冻结，后台与断线例子进入测试。它用于游戏体验的一致性，不宣称可完全证明人的注意力。

家具：
- 以最终 Figma 的布局与摆放交互为准；把设计中的明确操作/摆放结果映射为 action_id，后端验证合法性后读取对应分值，不追加自动心理推断或自行校正 T 分值。
- 不在玩家 UI 或待定项中展示额外的家具解释争议；UAT 仍展示真实 action、对应 A/V/T/F 增量和关卡累计。
- 如果最终设计包含拖动，保存 normalized x/y、rotation、家具 ID 与布局版本，用于恢复和屏幕适配；坐标不自动推导新的评分公式。
- 不新增自由布局自动分类算法或自拟整齐度/靠墙数值阈值。接入最终 Figma 时记录 UI 操作到既有 action 的对应关系；设计未明确的触发映射不能擅自编造。
- 只有有效确认 action 计分，预览、移动中间态和网络重试不累计。

## 8. 配置发布与调分流程

首版建议用经过校验的 JSON/YAML + Git PR 管理规则，数据库保存已发布不可变快照。暂不建设完整管理后台；架构保留相同 schema 的后续管理界面。

~~~
草案 → schema校验 → 合法路径与分布检查 → 内容评审
     → PR合并 → 生成不可变版本 → George在目标环境激活 → 仅新会话生效
~~~

每个会话锁定 content_version、scoring_version、persona_version、固定 enabled_groups 和 hash。事件分值、alpha、B、关卡权重、阈值、tie_policy、规则合并语义任一变化都生成新评分版本。内容结构和规则兼容性同时校验。

新规则发布时：
- 老会话继续使用开局规则，包括刷新和中途返回。
- 老结果保持原样；要做历史对比，产生独立 analysis_run/result_snapshot 并记录 source_result_id，不覆盖玩家原结果。
- 仅当原始动作足够支持新规则时才可重算；缺少新的空间/时间证据标为不可重算。
- 回退只切换新会话指向的已发布版本，不删除历史版本。
- 规则文件含分值，不直接下发到前端资产中；客户端内容 manifest 仅包含展示与可交互信息。

配置发布器必须拒绝：权重总和非 1、负权重、缺失四关/四轴、重复 ID、向量超出允许范围、未定义选择、无界重复计分、非法或零归一分母、未确认关键边界、缺失 16 型映射、未解决的依赖、标记为 draft 的配置。

[配置草案](examples/scoring-policy.draft.json) 展示结构、已确认行为语义和 PDF 的 L4 四个分值，不是完整评分库；含 publishable=false 和 unresolved 项，不能用于真实会话。

## 9. 评分验收

- 四关每轴最大理论贡献为 20/30/30/20；例子得到 18。
- 重发动作、双击、回放已消费动作不增加分数。
- 断网或关闭后恢复 outbox 使用原 action_id；家具草稿恢复不计分，离开期间不增加有效计时；详见 [场景保存与恢复](save-and-resume.md)。
- L1 所有符合条件的复合/宽泛规则均计入，每条贡献可查；重复请求同一规则不重复入账。船桨第 5 次触发一次，不按五次累加同一规则。
- L2 每局固定四组，刷新不丢组；拒绝钥匙/半开门后的通行路径待设计师决定，决定前不得声称该分支已通过完整验收。
- L2“先否后是”的序列规则与 L1 的全部匹配累加分别配置；不能套用 L2 的单一终态处理抑制 L1 合法贡献。未看到不等于拒绝。
- 14999/15000ms 返回主厅均按短寻找，持续寻找至 15001ms 才满足长寻找；后台/旋屏/断线不增加有效时长。
- 桌面/手机的同一有效家具 action 使用相同分值；按最终 Figma 交互验证 action 合法性，预览和重复请求不计分。
- 阈值 -epsilon/0/+epsilon、四轴组合到 16 型全部覆盖。
- 新版本不改变旧会话、旧结果；重算产生独立记录。
- 穷举/采样结果若某些类型不可达，要报告规则问题，不能偷偷补分使 16 型“看起来都有”。
